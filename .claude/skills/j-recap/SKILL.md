# j-recap

## Overview

Turns a period's work into a **third-party-readable recap** — X 投稿レベルの短文と、日報寄りのまとめ段落。読み手が**社外／第三者**である点が本質で、`j-log`（内部再現ログ）とも `j-doc`（社内ドキュメント）とも異なる。出力は**チャットのみ**（永続化しない）。

**Core principle — 記録だけで完了判定しない。** 会話記録は「何を話したか」であって「何が完了したか」ではない。記録で全体像を拾い、**git / PR の実体で裏取りしてステータスを確定する**。この裏取りが、コミットの羅列で終わる単なるログとの決定的な違い。

## Flow

1. **対象を決める** — `$ARGUMENTS` で上書き、省略時は**今日**（`currentDate` を基準にし、時刻取得 API は使わない）。
   - `YYYY-MM-DD` / `this-week` / `last-week` / `A..B` の範囲を受ける。
   - プロジェクト名（例 `joifup`）があればそのリポジトリに絞る。省略時は横断（その期間に触れた全プロジェクト）。
2. **拾う（breadth）** — `agentType: episodic-memory:search-conversations` サブエージェントに、対象期間の全セッションを**タスク／リポジトリ／成果物（コミット・PR・作成ファイル）単位で構造化**して報告させる。**憶測を禁じ、記録ベースの事実のみ**。→ タスク候補リストを得る。
3. **裏取り（truth）** — 各候補について対象リポジトリで実体を確認しステータスを確定する。
   - `git -C <repo> log --all --since=<start> --until=<end>`（対象期間・**全ブランチ**）。使えれば `gh pr` でマージ状況も。
   - **当日コミットが無い候補は落とす**（記録の雑音）。**記録と実体が食い違えば実体を優先**。
   - ここで得た**ハッシュ・PR 番号は完了判定の根拠に使うだけで、出力には出さない**。
4. **サニタイズ** — 内部識別子（`TASK-<n>`・内部リポジトリ名・未公開の固有名詞・社内ツール名）と機微情報を一般化／伏字にする。例:「TASK-88 richEditor round-trip audit」→「エディタの Markdown 往復変換の忠実性改善」。迷うものは丸めるか省く。
   - **主語（プロダクト本体）の扱い**: 読み物には主語が要る。**未公開／内部プロダクトの名前は出さず**、必要なら中立的なカテゴリで補う（例:「自作のタスク管理ツール」）。カテゴリすら特定につながるなら主語を省いて作業だけを語る。**公開済みで名指しして問題ないプロダクト**は、ユーザーがそう指定した場合に限りそのまま名前を使ってよい。
5. **出力（2形式・チャットのみ）** — 各タスクを「**進捗ステータス＋概要**」で。
   - **A. 短文ポスト版** — 各タスク1〜数本、X にそのまま貼れる短さ（1本 ≈ 140字目安、絵文字／ハッシュタグは控えめ）。
   - **B. まとめ段落版** — その日の成果を数段落の読み物に（ブログ／日報寄り）。

## ステータス判定（実体ベース）

| ステータス | 判定根拠の例 |
|---|---|
| **完了** | PR マージ済み／UAT 承認済み／対象ブランチが `main` に到達 |
| **進行中** | feature/worktree にコミットはあるが未マージ、実装途中 |
| **設計・計画** | ドキュメント／spec 作成のみ、または着手予定としてタスク起票のみで、実装未着手 |

起票のみ・実体の薄い候補は、**成果として語る意味がある場合だけ**載せる（単なる ToDo 化は省く）。

## 出力フォーマット（例）

```
## 作業まとめ（2026-07-21）

### 短文ポスト版
1.（完了）エディタの Markdown 往復変換で崩れていた記法を洗い出し、
   忠実性を改善する修正をリリースまで完了。48ケースの回帰テスト付き。
2.（進行中）ファイル監視まわりで双方向リンクを自動同期する仕組みを設計中。

### まとめ段落版
今日は主にエディタの信頼性向上に取り組んだ。……（数段落）
```

## Common Mistakes

- **記録だけで完了判定する** — このスキルの存在理由。必ず git / PR で裏取りする。
- **コミットハッシュ・PR 番号・`TASK-<n>` を出力に混ぜる** — 外部向けには不要。根拠に留める。
- **サニタイズ漏れ** — 内部リポ名や未公開プロダクト名は保守的に丸める。外部公開事故に直結。
- **永続化してしまう** — このスキルはチャット出力のみ。ノート化したいなら `j-doc` / `j-log` を使う。
