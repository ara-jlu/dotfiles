# j-recap

## Overview

その日（既定）または指定期間の作業を、**プロジェクト × タスク単位**でまとめる。主用途は自分の**確認・共有**なので、プロジェクト名・タスク番号・ステータスは**そのまま出す**（外部公開向けにぼかしたい時だけ末尾のサニタイズを使う）。

**Core principle — 記録だけで完了判定しない。** 会話記録は「何を話したか」であって「何が完了したか」ではない。記録で全体像を拾い、**git / PR の実体で裏取りしてステータスを確定する**。さらに**正味（net）の成果で書く**：期間内の個々のコミットの途中経過（後の変更で相殺される増減）は拾わず、期間の始点→終点で実際に何が変わったかを語る。

## Flow

1. **対象を決める** — `$ARGUMENTS` で上書き、省略時は**今日**（`currentDate` 基準、時刻取得 API は使わない）。`YYYY-MM-DD` / `this-week` / `last-week` / `A..B` の範囲を受ける。プロジェクト名があればそのリポジトリに絞る（省略時は横断）。
2. **拾う（breadth）** — `agentType: episodic-memory:search-conversations` サブエージェントに、対象期間のセッションを**プロジェクト／タスク単位で構造化**して報告させる（憶測禁止・記録ベースの事実のみ）。→ タスク候補を得る。
3. **裏取り（truth）** — 各候補を対象リポジトリの実体で確定する。
   - `git -C <repo> log --all --since=<start> --until=<end>`（対象期間・**全ブランチ**）。可能なら `gh pr` でマージ状況も。
   - **期間全体の net の成果**で捉える（途中コミットの打ち消しは無視）。**当日コミットが無い候補は落とす**。**記録と実体が食い違えば実体を優先**。
   - タスク番号を拾う: `tasks/<番号>-*.md`（ファイル名番号＝主 ID）。frontmatter に `ID: TASK-N` があれば併記用に控える。
4. **まとめる（出力）** — 下記フォーマットで、**プロジェクトごとに束ねて**チャット出力する（外部共有時のみ Step 5 のサニタイズを適用）。
5. **（任意）サニタイズ** — 外部公開する時だけ: タスク番号・内部リポ名・未公開の固有名詞を一般化／伏字にする。

## 出力フォーマット

- **プロジェクトごとの見出し**（`### <project>`）の下に、そのプロジェクトのタスクを箇条書き。
- 各タスク: `絵文字 **<番号>（TASK-N があれば併記）: タイトル**（ステータス語）` ＋ 子箇条書きで要点2〜3点。
  - daemon `ID: TASK-N` があるものだけ `（TASK-116）` を添える。無ければ番号のみ。
- **私目線で書く**：一人称・過去形・自分が日報に書くような自然な言い回し（「〜した」「〜を作った」「今〜中」）。AI 目線の報告調（「新規開発」「レビュー待ち」「着手前の計画段階」）は避ける。
- ハッシュ・PR 番号は根拠に留め、本文には出さない。

| 絵文字 | ステータス | 実体の根拠 |
|---|---|---|
| ✅ | 完了 | PR マージ済み／承認済み／`main` に到達 |
| 🚧 | 進行中 | ブランチにコミットあり・未マージ、実装途中 |
| 📝 | 設計・計画 | 設計／spec／起票のみ、実装未着手 |

## 出力例

```
## 2026-07-26 の作業

### joifup
- 🚧 **108: relation の制御文字インジェクション対策**（進行中）
  - 双方向 relation の共有 renderer で制御文字をエスケープするセキュリティ対応
  - 設計 → 計画 → 実装まで済ませて、今 In progress。main にはまだ入れてない
- ✅ **PM 運用まわりの整理**（完了）
  - オーケストレーションのルールを `/joifup-pm` スキルに切り出し
  - tmux の pane レイアウトとセッション命名の規律を追加
- 📝 **109（TASK-116）: daemon の single-instance ロック＋doctor の stale-binary 検出**（再スコープ）
  - 対象範囲を絞り直したところ。まだ着手前

### dotfiles
- 🚧 **003: j-recap スキル**（レビュー中）
  - その日の作業をまとめるスキルを作った。今 PR を出してレビュー中
```

## Common Mistakes

- **記録だけで完了判定する** — このスキルの存在理由。必ず git / PR で裏取りする。
- **途中経過を拾う** — 期間内の中間コミット（後で相殺される増減）ではなく、**始点→終点の正味の成果**で書く。
- **AI 目線の報告調** — 「新規開発」「レビュー待ち」ではなく、自分が書くように「作った」「今レビュー中」。
- **ハッシュ・PR 番号を本文に出す** — 根拠に留める。
- **永続化してしまう** — チャット出力のみ。ノート化は `j-doc` / `j-log`。
