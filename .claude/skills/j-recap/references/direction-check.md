# 方向性の点検

## 概要

週次・月次の `j-recap` で、recap を出した後に「その作業が正しい方向か」を一段上の粒度で点検する手順。日々のタスクは目先の最善に最適化されるので、大きな粒度で方向がずれても、何をやったかのまとめからは見えない。**判定はスキル側でせず、本人が言語化する。** Claude は本人が答えた後に所見を述べる。点検を行う条件は `SKILL.md` の Step 1 にある。設計の根拠は dotfiles の `notes/document/012-j-recap-direction-check-design.md` にある。

## 3 つの問い

1. **いま最も不確実なことは何か。それはいつ検証されるか** ——「いつ」が遠いなら順序が間違っている。
2. **この期間に、外に出たものは何か** —— 内側の作業は無限に増やせる。外に出たものだけが検証である。
3. **得意なことに時間が寄っていないか** —— 得意な側に逃げるのは普遍的な構造で、しかも成果物が出るので正当に見える。

**外に出たとは、自分以外の人に届いたことを指す**（送信・面談・提出・返信など）。git に残る成果物は、それだけでは外に出たものに数えない。自分でマージする PR は内側の作業である。

## 前回の点検を拾う

点検を行うときは、Step 2 のサブエージェントとは別に、`agentType: episodic-memory:search-conversations` のサブエージェントを**並列に** dispatch する。Step 2 の依頼は期間で絞った報告なので、期間を問わないこの検索を相乗りさせない。依頼文は次のとおり（`<TODAY>` は今日の日付、`<BEFORE>` は今日の 5 日前の日付に置き換える）。

```
j-recap の週次・月次の振り返りで出る「方向性の点検」の、過去の対話を探してください。点検の問いは次の 3 つです: ①いま最も不確実なことは何か・それはいつ検証されるか ②この期間に外に出たものは何か ③得意なことに時間が寄っていないか。

- 対象: <TODAY> より 5 日以上前の対話。検索の before を <BEFORE> に置き、after を新しい側から順に広げて探してください（例: 14 日前 → 30 日前 → 90 日前）。意味の近さの順位だけで選ばず、日付が新しいものを優先してください。
- 対象から除くもの: j-recap を週次・月次の期間で実際に呼んだ会話の中で、本人が自分の状況として答えたものだけを数えてください。j-recap スキルや方向性の点検そのものを設計・実装・テストしている会話（架空の回答や出力例を含む）は除いてください。
- 報告するもの:
  1. 本人が①に答えた点検のうち、直近のもの。その日付、本人が答えた①（何が最も不確実か・それはいつ検証されるか。複数あればすべて）、本人が答えた②。
  2. その点検より後に、本人が答えずに終わった点検（辞退した・問いが出たまま会話が終わった）があれば、その日付。
- 本人の言葉は記録からそのまま引いてください。見つからなければ「見つからない」と報告し、推測で埋めないでください。
```

5 日未満を除くのは、同じ週に `last-week` と `this-week` を続けて呼んだときに、直前の点検と比べてしまわないためである。回答の無い点検を前回として拾うと比較が抜け、しかも先送りしたい週ほど点検は飛ばされやすい。だから答えた点検と比べ、答えなかった点検は日付だけを事実として並べる。

**このサブエージェントは、問い（手順 1）を出すところまでは待たなくてよい。辞退を受けて事実の一行を出す前（手順 1）、所見（手順 3）、前回と並べる（手順 4）の前には必ず結果を待つ。** 待たずに進むと、前回があるのに「見つからない」と書き、期日のずれも止める条件も黙って落ちる。

拾えない（記録が無い・検索に掛からない）ことはある。そのときは、そのことを一言書いて先に進む。

## Step 2 の依頼に足すもの

点検を行うときは、Step 2 のサブエージェントへの依頼に次の一文を足す。②の候補と所見の材料にするためである。

```
期間内の、外に出た行動（送信・面談・提出・返信など、自分以外の人に届いたもの）も、タスクの要約に吸収させずに、別の項目として拾って報告してください。
```

## 手順

Step 4 で recap を出した後に行う。**外部共有のとき**（共有用のまとめを求められ、Step 6 のサニタイズを行うとき）は、サニタイズ版を先に出してから点検に入る。点検はサニタイズ版に含めない。点検は自分向けの対話である。

1. **問う。** 3 つの問いを 1 つのメッセージで出し、本人の回答を待つ。「分からない」と答えてもよいと添える（答えられないこと自体が情報である）。問いの文面は期間に合わせて「この期間」と書き、「今週」と決め打ちしない。**回答の前に、Claude の見立てや候補を出さない。** 本人が言語化する前に出すと、本人の答えが Claude の候補に引き寄せられる。
   - **本人が点検を辞退したら**（「今はいい」など）、それ以上問わない。ただし、前回の点検を拾う結果を待ってから、前回の点検が見つかっていれば、終える前に事実を一行だけ示す: 前回の日付・前回の①（何が・いつ）・今日の日付と、前回の期日がすでに過ぎていればそのこと。これは見立てではなく事実なので、上の規律に反しない。先送りしている週ほど辞退されやすく、辞退で事実まで消えると、言う場所が無い形に戻るからである。
2. **詰まった問いにだけ候補を出す。** 本人が「分からない」と答えた問い、または答えに詰まった問いにだけ、候補を 2〜3 個出す。本人が選ぶか書き直す。候補の根拠は下の「根拠の範囲」に従う。
3. **所見を述べる。** 回答が揃ったら、問いごとに Claude の所見を一言ずつ述べる。どの事実から言うのかを示す。**言いにくいことも言う** —— 気づいていても聞かれるまで言わないことが、この点検で防ぎたいことである。ただし、方向を変えるかどうかの結論は本人に残す。**所見を新しい準備タスクの提案に変えない。** どんな指摘も「その対策タスク」に変換されると、内側の作業がまた増える。
4. **前回と並べる。** 前回の点検が見つかれば、その日付と前回の①（何が・いつ）を、今回の①と並べて示す。並べるのは「同じかどうか」だけではない。**検証の期日が前回より後ろへずれていれば、ずれたことを事実として示す。前回の期日がすでに過ぎていて、まだ検証されていなければ、そのことも示す。** 期日を自分で動かせることが、先送りの構造そのものだからである。前回より後に答えなかった点検があれば、その日付も並べる。前回の点検が見つからなければ、その旨を一言書く。
   - ①に複数の答え（事業ごとなど）が来たときは、項目ごとに前回の答えと内容で対応付けて、期日のずれと「同じ」かを見る。
   - 本人が「分からない」のまま候補を選ばなかった①は、「同じ」かの判定に使わず、答えられなかったことを事実として並べる。
5. **止める条件を示す。** 次の 4 つがすべて当てはまるなら、「止める条件に当たっている」と事実として示す。
   - 今回の期間が 5 日以上である（週の頭の `this-week` のように期間が短いと、②が無いのは当たり前だからである）。
   - 前回の点検が 14 日以内である。
   - 前回の①と今回の①が同じである（何が最も不確実か、が同じ）。同じかは回答の文面を読んで判断する。
   - 今回の②が無い（本人の回答で、外に出たものが無い）。

   前回の点検が 14 日より前なら止める条件は当てず、前回から何日空いたかを示すに留める。**「止める」とは、内側の作業（新しい準備・制作・整備）を足すのを止め、①を検証する、外に出る行動を次に置くことを指す。** プロジェクトをやめることでも、いまのタスクを中断することでもない。

## 根拠の範囲

候補と所見の根拠は、問いによって分ける。Step 3 で確定する事実は git と PR が裏付ける作業だけであり、外に出た行動の多くはコミットを伴わず、時間の配分は git に無いからである。

- **①:** recap の事実（Step 3 で確定したタスクと成果）と、Step 2 の会話記録。
- **②:** Step 2 の会話記録（Step 3 で落とす前の候補と、上の「Step 2 の依頼に足すもの」で拾った外に出た行動を含む）と、本人の回答。git に残る成果物を、外に出たものとして数えない。
- **③:** recap の事実と会話記録から、どの種類の作業にタスクやセッションが寄っているかを推す。時間を直接測ったものではないことを、所見の中で明示する。何が「得意なこと」かは、本人が回答で挙げたものを足場にする。挙げていなければ、「外に出ない作業（制作・整備）」と「外に出る作業」の配分に読み替え、②とつなげて見る。

## 出力例

問いのメッセージ:

```
## 方向性の点検

この期間について 3 つだけ聞かせてください。「分からない」でも大丈夫です（答えられないこと自体が情報です）。

1. いま最も不確実なことは何ですか。それはいつ検証されますか。
2. この期間に、外に出たもの（自分以外の人に届いたもの）は何ですか。
3. 得意なことに時間が寄っていませんか。
```

本人の回答を受けた後の所見のメッセージ（`last-week` を 2026-10-20 に呼び、前回の点検は 2026-10-13、本人の回答は ①「X が通用するか。10/24 の面談で確かめる」②「無し」③「寄っているかもしれない。ツールを触っている時間が長い」のとき）:

```
### 所見

- ①: 前回（10/13）も「X が通用するか」で、そのときの期日は 10/17 だった。今回は 10/24 で、期日が 1 週間後ろへずれている。10/17 はすでに過ぎていて、この期間の記録に X を確かめた痕跡は無い。
- ②: 外に出たものは無い、という答えと記録は一致している。git には PR のマージが 3 件あるが、どれも自分でマージした内側の作業である。
- ③: 本人の言う「ツールを触る時間」は記録とも合う。この期間のタスクは 5 件中 4 件がツールの改修だった。時間を測ったものではなく、タスクの数からの推定である。①の X を確かめる作業は、この 4 件の中に無い。

前回（10/13）と①が同じで、②が無い。止める条件に当たっている。内側の作業を足すのを止めて、X を確かめる外向きの行動を次に置く、という条件である。どうするかは任せる。
```
