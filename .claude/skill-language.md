# 自作スキルの記述言語ルール

`CLAUDE.md` § 言語 の「自作スキルの SKILL.md: 日本語」の細則。**自作スキル（`.claude/skills/j-*` と `md2joifup`）を新規作成・改訂するときに読む。** superpowers / ECC のスキルは無改変で使うので対象外。

以下はすべて `tasks/009` で9ファイルを日本語化した際に、実際の欠陥から確定したものである。推測ではない。

## 借用語を英語で残すか訳すか

**判断基準は1つ: 著者自身の日本語がその語をどう書いているか。** `notes/` と既存の日本語スキルを grep して、実際の用法に合わせる。一般論で決めない。

この基準による既決:

| 語 | 扱い | 根拠 |
|---|---|---|
| `house-style` / `ad-hoc` | 英語のまま（`house-style` はハイフン付き） | `notes/plan/001-j-task.md:18,25`、`notes/document/001-harness-as-built-architecture.md:33`、`j-pr/references/pr-body.md:3` |
| `clean` / `dirty` | 両方英語（対なので片方だけカタカナにしない） | git の作業ツリー状態を指す用語 |
| `landscape` | 「全体像」 | `notes/document/001-harness-as-built-architecture.md:15`、`j-recap/SKILL.md:14` |
| `dev flow` | 「開発フロー」（スキル名 `j-devflow` は識別子なのでそのまま） | `notes/document/001-dev-flow-redesign.md` の title・本文、`001-harness-as-built-architecture.md:40` |
| `surgical` | 「外科的」 | `notes/log/001-ai-harness-full-session.md:146,149` |
| `frontmatter` / `diff` / `worktree` / `subagent` / `directional` | 英語のまま | 原語で定着している技術識別子 |

## 訳の強さを変えない

- **`should` を `なければならない` に強めない。** 強める方向でも改変は改変（`〜するようにする` / `〜すべきである`）。
- **`never` / `MUST` / `NOT` は強さを保つ。** `**never** set Done` → `**絶対に** Done にしない`。禁止を推奨に落とさない。
- **`fails loudly` / `stops loudly` は「大きな声で」と訳さない** — CLI の挙動を指す慣用表現なので「明示的にエラーで落ちる」「明示的に停止する」。対になる `silently` は「黙って」でよい。
- **`all` を含む否定に注意。** `cannot clear all X` は「X が1つでも残れば該当」の意味だが、「すべて解消できない」と訳すと「1つも解消できない場合のみ該当」とも読める。「解消しきれない」とする。
- **修飾の係り先を変えない。** 括弧が最後の要素だけに係るのか全体に係るのかで意味が変わる（例: `NOT for A, B, or C (that is X)` の括弧は C にのみ係る。3つ並べて「それは X の役割」と訳すと A と B も X の仕事に見える）。

## 語順・句読点

- **`**報告する**` は目的語を先に置く。** `…のパスを**報告する**。` とする。`**報告する**：…のパス` は英語語順の calque。
- **英語の副詞は日本語の副詞にする。** 「論理的に」であって「ロジックで」ではない。名詞句に変えると訳文調になる。
- **括弧での言い換えは「（それは `X` の役割）」**。`（それは `X`）` の裸形は直訳。節が完全文なら `— それは X の役割` の同格形を使う。
- **全角の `；` を使わない。** 原文が `;` で繋いでいても 。 で切るか 、 で繋ぐ。
  - **置き換えは機械的にやらず読んで決める。** 前後の両方に述語があれば 。。左側が**述語の無い列挙やダッシュによる言い換え**なら 。（体言止め＋。は日本語のリファレンス文体として自然で、末尾の述語が列挙全体を支配して読める誤読も防ぐ）。、 で繋ぐのは断片が**後続節の一部**である場合（括弧内の同格列挙など）に限る。
- **全角の `？` の後に空白を入れない。** `clean か？dirty なら` と書く。
- **英数字と日本語の間に半角スペースを入れる。** `完了した feature ブランチ`。数値と単位の間も空ける（`1,500 B`）。
- **ハード折り返しをしない。** 1段落1行。1,000文字を超えても改行しない（`tasks/008`）。

## 語彙の統一

- 見出しは固定の語彙表に従う（下記）。ファイルごとに訳を発明しない。
- `single` = 単一 / `standalone` = 単体。
- `default` = 既定（「デフォルト」と混在させない）。
- `(optional)` = （任意）。
- **gloss をファイル内で不揃いにしない。** 原文が `Discord` だけなら `Discord` と書き、ある箇所だけ `Discord 通知` に膨らませない。
- **英語のまま残すスローガンには初出時に一度だけ括弧で言い換えを添えてよい**（`**accuracy over recall**（記憶より正確さ）`）。二度目以降は付けない。

### 見出しの語彙表

| 英語 | 日本語 |
|---|---|
| Overview | 概要 |
| When to Use | 使う場面 |
| Flow | 流れ |
| Steps | 手順 |
| Usage | 使い方 |
| Runbook | 手順書 |
| Guards | ガード |
| What it does | 何をするか |
| What the script guarantees | スクリプトが保証すること |
| ECC knowledge | ECC の活用 |
| Body | 本文 |
| Identifier | 識別子 |
| Common Mistakes | よくある失敗 |
| `<X>` content spec | `<X>` の内容規定 |

モード名・フラグ名・フェーズ名（`attended` / `-auto` / `-light` / `full` / `Phase A` / `GATE 1`）は識別子なので見出し内でも英語のまま。`(default)` のみ `（既定）` にする。

## `description`

- **日本語の起動語を含める。** これは**追加が規定されている唯一の場所**である（本文では原文に無いものを足さないが、`description` は起動判定に使われるため、ユーザーが実際に打つ語を入れる）。英語原文に起動語が無くても入れる。
- 末尾は「…に該当する場合。」で止める（「…に該当する場合に使う。」とすると1つの `description` に 使う が2回出る）。
- 固有語（`Joifup` / `PR` / `UAT` / `Discord` / `superpowers`）は英語のまま。
- **例外: `user-invocable` を持たないスキルには起動語を入れない。** `md2joifup` が該当する。ユーザーが語を打って起動する対象ではなく、他スキルが委譲して呼ぶため、架空のユーザー発話を足すとフロースキルを経由しない誤起動を招く。`description` は「どういうときに委譲すべきか」を述べるに留める。

## 英語のまま残すもの（一覧）

`name`、frontmatter のキー名、コマンド・パス・フラグ・環境変数、他スキル名と `agentType`、Joifup の status 値（`Not started` / `In progress` / `In review` / `Done` / `Cancelled`）とタグ名（`plan` / `document` / `log` / `research` / `memo`）、コミットメッセージ例、コードフェンスの中身、事故・タスクの参照番号。

## 既に日本語の箇所に手を入れない

著者が元から日本語で書いた段落・見出し・出力例は、後から確定した規約を遡って適用せず、バイト単位で保持する。生成物の仕様（スキルが**出力する**ドキュメントの見出し指定、タイトル書式、出力例のフェンス）も同様に形を変えない。

## 改訂時の検査

既存スキルを全面的に書き換えるときは、構造が変わっていないことを機械で確かめる。9ファイルの日本語化では旧版（`git show <base>:<path>`）と新版を比べて8条件を検査した: ①`##`/`###` 見出しの個数・順序と語彙表への適合 ②節ごとの箇条書き項目数 ③節ごとのテーブル行数 ④コードフェンスのバイト一致 ⑤frontmatter のキー集合 ⑥インラインコードの多重集合 ⑦`**強調**` の個数 ⑧段落行数。

**全行が変わる差分では「訳しただけ」を目視で検査できない。** 検査スクリプトは一度きりの作業用なのでコミットしない（`tasks/009` の実績）。
