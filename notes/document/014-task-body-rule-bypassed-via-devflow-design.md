# j-devflow 経由の起票で j-task の本文規則が適用されない

## 背景と問題

`j-task` は Task の本文を `## 概要` と `## 背景` だけに限り、分析・引用・実装方針・受け入れ基準を禁じている。規則の目的は、実装者が起票者の問題理解に縛られないようにすることである。

しかし規則は `j-task/SKILL.md` の文章にしか無く、実際にファイルを書く `md2joifup --db tasks` は本文を見ない。そして流れの中の起票 — ユーザーが「タスク起票して」と言ったとき、j-devflow の brainstorming で子タスクに分解したとき、最終レビューや fix ループで本ブランチでは閉じない残余が出たとき、PM セッションが申し送りを起票したとき — は `j-task` を起動せず `md2joifup` を直接叩いていた。fde の 043・049・050 と、046 の通読レビューから出た 057・058 がその実例で、`## 決めること` `## 落としてはいけないもの` `## やらないこと` `## 受け入れ基準` `## 出どころ` を持ち、2.8〜5.9 KB ある。

根本原因は規則の内容ではなく、**規則を持つスキルが起動されなかった**ことである（2026-09-22、ユーザー）。

一方で外れた本文には一次資料の引用と探索の手がかりが入っており、捨てると再取得に費用がかかる。ユーザーの方向づけ（2026-09-20）は「調査結果を一律で禁じる側には倒さない。起票時の事前調査をメモとして残せるようにし、実装セッションが検証済みの結論と受け取らない形にする」である。

## 決定事項

### 起票は j-task に集約する

流れの中の起票を含め、新しい Task を作るときは必ず `j-task` を経由する。`md2joifup --db tasks`（および `--new-task`）を呼ぶのは `j-task` の内部からに限る。機械検査は置かず、起動を確実にする側から直す。

- `j-task/SKILL.md` の `description` に、実際に発火しなかった発話を起動語として足す: 「タスク起票して」「タスクにしておいて」「別タスクに切り出して」「follow-up を起票」「残余を起票」「申し送りのタスクを作って」。さらに j-devflow・brainstorming・最終レビュー・PM セッションの流れの中で Task を作るときも経由すると明記する。
- `j-devflow/SKILL.md`: 流れの中で生まれる Task（brainstorming の分解で出る子タスク、最終レビュー・fix ループで本ブランチで閉じない残余）も `/j-task` 経由と明記し、「よくある失敗」に「残余を `md2joifup --db tasks` で直接起票する」を足す。
- `j-finish/SKILL.md`: 「よくある失敗」に「残余タスクを `j-task` を経由せず起票する」を足す。j-finish 自身は起票しないので手順は触らない。
- `md2joifup/SKILL.md`: 「Task 作成（tasks db）」の段落に「本文の規則は `j-task` が持つ。呼び出すのは `j-task` の内部からに限る（`--new-task` も同様）」を足す。`user-invocable` を持たないので `description` に起動語は足さない。
- `CLAUDE.md`（global）は触らない。規則はスキルに閉じる。

### 本文に第 3 の節「起票時のメモ（未検証）」を許す

許す節構成を `## 概要`（必須）＋ `## 背景`（任意）＋ `## 起票時のメモ（未検証）`（任意）にする。他の `##` 節は置かない。

- **置いてよいもの:** 一次資料の引用と行番号、探索の手がかり（どのファイル・どのタスク・どの決定を先に読むか）、危ないところ（壊しやすい既存の資源）、決めることの候補、やらないことの候補、出どころ（どのレビュー・実験から出たか。実験なら方法も）。
- **契約:** この節は brainstorming の出発点の材料であって結論ではない。実装セッションは検証してから使う。行番号は目安で、文字列で探す（fde `tasks/058` が本文に書いていた注意をそのまま規則にする）。見出しの「未検証」がその印である。
- **引き続き禁じるもの:** 受け入れ基準・実装方針・確定した設計判断。これらは brainstorming・plan・PR 本文に置き場所がある。「決めること」「やらないこと」を独立した `##` 節にせず、メモ節の中の箇条書きに留める。
- **サイズ:** 概要 3〜5 行、背景 3 行以内は維持する。メモ節は「捨てると再取得に費用がかかるものだけ」を置き、上限は置かない。
- 「よくある失敗」に「流れの中の起票で `j-task` を飛ばして `md2joifup` を直接叩く」「メモ節の内容を検証済みとして brainstorming を省く」を足す。

### joifup-pm の矛盾は申し送る

`joifup-pm/SKILL.md`（joifup リポジトリ）§4 起票の「残余の起票は『着手時に設計し直さない』粒度で書く。復帰先を要素レベルで確定し、代替案を却下する理由まで書く」は、`j-task` の「設計判断は brainstorming に属する」と衝突する。別リポジトリなので本ブランチでは直さず、joifup リポジトリの `tasks/` に `j-task` で起票して申し送る。本文はメモ節の形で書き、衝突箇所の引用とこの設計文書へのポインタを入れる — 新しい規則の最初の実例になる。起票は joifup 側の `pnpm run task:new` を通す（main への直接 commit だと CI の `task-ids` job で測れない）。

申し送り先の起票ファイルは、`CLAUDE.md` § レビュー統合 の例外規定どおり最終レビューのパッケージに含める。

## 線引き — やらないこと

- **md2joifup での機械検査。** ユーザーの見立てでは原因は経由漏れであり、検査は過剰。再発したら再検討する。
- **既存 fde タスクの遡及修正。** 実装済み・進行中のものを書き換えても得るものが無い。
- **joifup-pm の直接編集。** リポジトリが違う。申し送りで扱う。
- **規則を実態に寄せる案（`## 決めること` 等を正式節にする）。** 規則の目的（実装者を起票者の理解に縛らない）を崩す。

## 検証

コードは無いので自動テストは無い。検証は次の 3 点である。

- 各 SKILL.md の改訂が `.claude/rules/skill-language.md` の規約に沿うこと: 見出しは語彙表の語、`description` の末尾は「…に該当する場合。」、日本語を桁数で折り返さない、英数字と日本語の間に半角スペース。改訂後に grep と目視で確かめる。
- 改訂後の `j-task/SKILL.md` を読んだ fresh subagent に fde `tasks/058` 相当の起票依頼を渡し、出力が `## 概要` / `## 背景` / `## 起票時のメモ（未検証）` に収まることを 1 回試す。最終レビューの前に orchestrator が行う。
- joifup 側の申し送りタスクが、新しい規則の形（3 節以内）で起票されていること。

効いているかどうかは、以後の起票で `j-task` が起動されるか（ファイルの節構成で分かる）を観察して判断する。
