# 判断の原則を CLAUDE.md に載せる

## 背景と問題

判断の原則は個人の notes（git 管理外）に文書として書いてあるが、文書に書いただけでは日々の判断で発火しない。恐怖はその場に合った正当な理由を毎回連れてくるので、理由の側を潰すことはできず、**判断の場に原則が居合わせる必要がある**。

判断の場のひとつが Claude Code のセッションである。`~/.claude/CLAUDE.md`（= dotfiles の `.claude/CLAUDE.md`）は全セッションが毎回読むので、ここに載せれば Claude が原則を持って対話に居合わせる。ただし毎回読む面なので長く書けない。何を載せて何を載せないかの線引きが、このタスクの実体である。

## 決定事項

### 載せる文

`.claude/CLAUDE.md` の `# Development Rules` 直下に、次の節を追加する。

```markdown
## 判断の原則

回復不能なリスクは徹底的に避け、回復可能なリスクは速く取る。自分の作業にも、ユーザーの判断への問い返しにも当てる。
```

見出し・空行・本文・区切りの空行の 4 行を挿入する。変更するファイルはこれだけである。

### 効かせる対象は両方

Claude 自身の作業判断（過剰な準備・確認・設計）と、ユーザーが判断している場面（準備タスクを増やす、期限を後ろへ動かす）の両方に当てる。`# Development Rules` の下に置くと Claude は自分の作業にだけ当てると読むので、第 2 文で対象を明示する。この 1 文が無いと、タスクの動機（ユーザーの判断の場に居合わせる）が落ちる。

### 原典へのポインタは置かない

原典は dotfiles と無関係な個人の notes にあり、dotfiles は public リポジトリでもある。CLAUDE.md は単独で成り立つ形にし、根拠はこの設計書に残す。

## 線引き — 載せなかったもの

原典には原則が 3 つと、運用の問いがいくつかある。載せたのは原則 1 だけである。

- **原則 2「失敗は自分だけが覚えている」。** セッション中に独立して発火する場面が無い。相手の反応を恐れて外に出すのをためらう場面は、「恥をかくのは回復可能」として原則 1 に吸われる。さらに原典自身が「言い聞かせても効かない。効くのは予測と結果のズレの記録だけ」と書いており、CLAUDE.md に 1 行で置くのはまさに言い聞かせの形である。記録という行為はセッションの外で行うもので、CLAUDE.md の担当ではない。
- **原則 3「反証できないものに長時間思考しない」。** 反証できない懸念で止まっている状態は、止まっている限り回復可能なリスクを取っていないので、原則 1 に吸われる。「観測窓を先に決めて待つ」は対人の待ち方で、セッション中には発火しない。
- **運用の問い（「これをやると検証は何日遅れるか」「それは今日やることを止める理由か」）。** 手順である。Claude 5 世代向けの指針は「手順ではなく判断を与える」なので、判断の姿勢だけを載せ、問いの形は Claude の判断に委ねる。
- **理由・経緯・表。** すべて原典に置いたままにする。CLAUDE.md は「消すと Claude が間違えるか」の基準で各行を選ぶ面であり、理由は基準を満たさない。

## 根拠にした調査

CLAUDE.md の書き方について、2026-09-22 時点で調べた。

- Anthropic 公式の best practices: 「各行について『これを消すと Claude が間違えるか』を問い、そうでなければ削る」「長い CLAUDE.md は実際の指示を無視させる」「短く、人が読める形で」。
- Claude Code チームの記事（Claude 5 世代向けにシステムプロンプトの 80% を削っても性能が落ちなかった）: 「ルールを与える」から「判断を任せる」へ、「手順を書く」から「結果とガードレールを書く」へ。詳細は progressive disclosure で参照先に置く。ただし「重要な領域では制約してよい」。
- 派生記事の整理: 削ってよいのは周囲のコンテキストから導出できるもの。価値観・リスク姿勢・「done」の定義のように、リポジトリからは導出できないものは、常時読む側に短く残す。判断の原則はこの種類である。

以上から、載せる形は「判断の姿勢を 1 文、理由なし、手順なし」に定まった。最初の案は原典の理由と手順を持ち込んで 5 行になっており、公式の基準に照らして長かった。

## 検証

markdown の 4 行追加なので自動テストは無い。検証は次の 2 点である。

- diff が上記の 4 行の追加だけであること。
- 追加した日本語が桁数で折り返されていないこと（`CLAUDE.md` § 言語 の規約）。

効いているかどうかは、以後のセッションで Claude が準備を増やす方向の判断に対して問い返すかを観察して判断する。効かなければ文言を見直すが、行数は増やさない。
