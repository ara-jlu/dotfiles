# 日本語のハード折り返しをやめる（設計）

## 目的

日本語の md 本文とコメントが桁数で折り返されている。日本語は語の間に空白が無いため、折り返しは語や句の途中で割れる。エディタが soft-wrap するので二重に折れ、意味と無関係な位置で2回切れる。折り返さないことを規約として置き、既存分は機械的に結合する。

## 実測

`~/Joifup` 配下の全リポジトリを測った。「折り返された行」の定義は「次の行が同じ段落の続きである行」（空行でも、見出し・リスト・表・フェンスの開始でもない行が次に来る）。frontmatter とコードフェンスの中は数えていない。

「うち日本語」は行単位で数えた概算である（変換の対象判定は後述のとおり段落単位なので、実際の対象はこれより少し多い）。日本語の折り返し行は合計およそ 21,940 行で、その 98% が joifup と fde にある。nightmill が 3,036 段落行で折り返し 10 行しかないことは、折り返しが必然ではないことを示している。

## 規約

置き場所は**グローバル `CLAUDE.md` の § 言語**。`~/.claude/CLAUDE.md` は `dotfiles/.claude/CLAUDE.md` への symlink であり、全リポジトリに届く経路はこれだけである。`.claude/rules/` は symlink されておらず dotfiles 内でしか効かないので、全 repo に効かせる規約の置き場所にならない（`tasks/009` が作った `.claude/rules/skill-language.md` は自作スキルの md だけが対象なので、dotfiles 内で閉じていて問題ない）。

判断の余地がない規則なので、細則ファイルは作らず一文で置く。

> **日本語の本文とコメントは桁数で折り返さない**（1段落＝1行）。エディタが soft-wrap するので二重に折れ、日本語は語の間に空白が無いため語の途中で切れる。

## 変換の規則

段落の途中で改行されている行を次の行と結合する。

**触らないもの:**

- frontmatter（ファイル先頭の `---` ブロック）
- コードフェンス（``` および ~~~）の中
- 表の行（`|` で始まる）
- 見出し（`#`）、引用（`>`）、水平線
- 行末が半角空白2つ、または `\` で終わる行 —— markdown の意図的なハードブレイクである
- 日本語を含まない段落 —— 英語は空白で切れるので害が小さく、規約も日本語に限っている。**判定は行単位ではなく段落単位で行う。** 行単位にすると、英語の行で始まって日本語の行が続く段落が途中までしか結合されず、かえって読みにくい形で残る

**結合するもの:** 上記に当たらない段落本文の行と、箇条書き（`-` / `1.`）の項目本文が複数行に折られている場合の継続行。継続行は親の行に結合する。

**結合点の空白:** 結合点の前後のどちらかが ASCII 英数なら半角空白1つを入れ、日本語どうしなら空白なしで繋ぐ。

折り返しで消えた空白は復元できないので、既存の本文の慣習に寄せて決めた。行の内側（改行をまたがない位置）で英数字と日本語の境界に空白が入っている割合を joifup・fde・dotfiles の notes で数えると、日本語 → 英数字が 38,190 / 68,846（55%）、英数字 → 日本語が 60,260 / 85,315（71%）で、どちらも空白を入れる側が多数派である。`Claude Code` のように英数字の語句が行をまたいで割れた場合に語が潰れるのは、この規則でも防げる。

## 検証

21,940 行を目視せずに安全だと言える根拠を、スクリプト側に持たせる。ファイルごとに変換前後を比べ、次の2つがともに成り立つときだけ書き戻す。

1. **段落テキストが文字単位で一致する。** 変換後から改行と結合時に挿入した空白を除いたものが、変換前から改行を除いたものと一致する。文字の欠落・重複・順序変更が無いことを保証する。
2. **構造の数が不変である。** 見出し・コードフェンス・リスト項目・表行の数が前後で変わらない。

どちらかが崩れたファイルは変換せず、失敗として報告する。

スクリプトには「触らないもの」の項目ごとに単体テストを付ける。フェンス内・表・ハードブレイク・frontmatter・英語段落がそれぞれ保存されること、日英境界に空白が入ること、リスト継続行が結合されることを固定する。

## 適用の範囲と順序

**この作業（tasks/008）で行うのは、規約の追加と dotfiles 自身の変換、そして変換手順の確定まで。** スクリプトは scratchpad に置き、リポジトリにはコミットしない。一度やれば済む機械的変換であり、再発は規約が止めるので、恒久的な道具を抱える理由が無い。

他の repo は同じ手順を repo ごとに別 PR で順次適用する。適用時の状態はそれぞれ違う:

- **joifup**（13,571 行）: main に未コミット変更が5ファイルある。先に片づけてから当てる。
- **fde**（7,963 行）: 進行中ブランチ `feature-049`（In review）が `notes/document` を14ファイル触っている。**049 をマージしてから当てる。** 先に main を変換すると 049 のマージが全面衝突する。
- **web-extension-lab / perio-voice / joifup-blog / nightmill / minecraft / cosmodoro**（合計 287 行）: 小規模なのでまとめて順次。
- **`~/Joifup/notes` と `~/Joifup/tasks`**（52 行）: git 管理外なので PR は無く、直接変換する。

コード側のコメントの折り返しは本タスクの対象外である。`tasks/007` が対象のコメントブロックをどのみち書き換えるので、そこで済む。先に整形すると 007 で削除する行を触ることになり二重になる。
